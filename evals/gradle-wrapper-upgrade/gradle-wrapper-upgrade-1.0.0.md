## Findings

<sub><em>Interpretation generated by an agent from the tables in this report, not reviewed by a person. It is a reading of the data, not part of the measurements. To replace these findings with your own, write <code>history/gradle-wrapper-upgrade/1.0.0/findings.md</code>.</em></sub>

**From about half the checks to all or nearly all.** `claude-opus-5-5`, `claude-sonnet-5`, `deepseek-v4-pro`, `gemini-3-8-flash` and `gpt-5-6-luna` pass every check with the skill, `claude-sonnet-5` all but one. The gains are mostly in the blocked-upgrade scenarios (pinned `wrapper` task, rollback, reporting the block), far beyond what two identical runs differed by.

**Mostly at the same or lower cost.** For `claude-opus-5-5`, `claude-sonnet-5`, `deepseek-v4-pro` and `gemini-3-8-flash` the runs with the skill cost about the same or less in total and took similar or less time, `gemini-3-8-flash` about half. `gpt-5-6-luna` is the exception, at about half again the cost of its runs without the skill and somewhat more time.

**From failing most checks to passing most.** `claude-haiku-4-5-20251001` gains as many checks as any model, ending with all but three passed; it still fails `advised-next-step` in both blocked scenarios and `snapshot-verified`. Cost is about the same, time lower.

**Checks lost with the skill.** `qwen3-6-35b-a3b-coding-nvfp4` loses both `advice-only` checks, upgrading the wrapper when asked only how, and `no-collateral-damage` in `upgrade-blocked-git`, while no check differed between its identical runs. Its gains are fewer than any other model's, and `rolled-back` fails with and without the skill.

- `upgrade-blocked` and `upgrade-blocked-git` / `wrapper-task-pinned` (a `wrapper` command with `--gradle-version` 9.0.0 and `--gradle-distribution-sha256-sum`): failed without and passed with for all 7 models in both scenarios.
- `upgrade-blocked` / `reported-blocked` (a message stating the wrapper was rolled back or the upgrade blocked): failed without and passed with for all 7 models.
- `upgrade-blocked` and `upgrade-blocked-git` / `rolled-back`, and `upgrade-blocked-git` / `restored-to-head`: failed without the skill for all 7 models; passed with it for 6, with `qwen3-6-35b-a3b-coding-nvfp4` failing in both arms.

**From the Notes, affecting single figures:**

- `claude-sonnet-5`'s one check failed with the skill, `advised-next-step` in `upgrade-blocked`, is a message that names 8.6 and the upgrade guide and also contains the phrase "latest 8.x", which the pattern excludes.
- `qwen3-6-35b-a3b-coding-nvfp4`'s `project-builds` failure without the skill in `sha-already-pinned` is a `NoSuchFileException` under `/tmp/gradle-9.0.0`, a directory the arm created and then removed; the other four checks in that arm passed.
- `qwen3-6-35b-a3b-coding-nvfp4`'s `no-collateral-damage` loss in `upgrade-blocked-git` is two modified `buildSrc` plugin sources.

## Notes

- `qwen3-6-35b-a3b-coding-nvfp4`: no price is configured, so no cost is recorded.
- Not every model ran on the same `claude-code` version: `2.1.233` for `qwen3-6-35b-a3b-coding-nvfp4`; `2.1.281` for `claude-haiku-4-5-20251001`, `claude-opus-5-5`, `claude-sonnet-5`.
- Turn, token and time limits were set per model, so they differ between models. Both runs of a comparison always had the same limits.
- No arm stopped at a turn, token or wall-clock limit, and every arm was graded: all 84 arms record a PASS or FAIL outcome with no limit recorded.
- `advised-next-step` on `upgrade-blocked`, `claude-sonnet-5` with the skill: the closing message names 8.6, links the Gradle 9.0.0 release notes and the Gradle 9 upgrade guide, and contains the phrase "not straight to the latest 8.x". The pattern's exclusion of "latest" followed by an 8.x version matches that phrase, and the check recorded FAIL.
- `project-builds` on `sha-already-pinned`, `qwen3-6-35b-a3b-coding-nvfp4` without the skill: `./gradlew build` exited non-zero with `java.nio.file.NoSuchFileException: /tmp/gradle-9.0.0/lib/gradle-base-diagnostics-9.0.0.jar`. The transcript shows the arm unpacked a Gradle 9.0.0 distribution to `/tmp/gradle-9.0.0`, ran `/tmp/gradle-9.0.0/bin/gradle wrapper --gradle-version 9.0.0`, and ran `rm -rf /tmp/gradle-9.0.0` as its last command. The other four checks in that arm recorded PASS.
- `no-collateral-damage` on `upgrade-blocked-git`, `qwen3-6-35b-a3b-coding-nvfp4` with the skill: the scorer recorded `FiringReportPlugin.java` and `KilnStampPlugin.java` under `buildSrc` as modified. The transcript shows the arm wrote both files after the `wrapper` task failed.
- `did-not-upgrade` on `advice-only`, `qwen3-6-35b-a3b-coding-nvfp4` with the skill: the final tree has `distributionUrl` naming `gradle-9.0.0-bin.zip`, a `distributionSha256Sum` line, and `gradlew` matching Gradle 9.0.0's. `explained-how` in the same arm found no message matching its command pattern.
- `no-collateral-damage` recorded PASS in every arm of `upgrade` and `sha-already-pinned`. The same script, run against the `sample-kiln-registry` manifest, recorded FAIL in arms of `upgrade-blocked` and `upgrade-blocked-git`, so the scorer produces both verdicts.
- `non-version-properties-preserved` recorded PASS in every arm of `upgrade` and `sha-already-pinned`. The scorer records FAIL when any of the six entries is missing or has a different value; an edit that changes only the `distributionUrl` and `distributionSha256Sum` lines leaves all six in place and records PASS.
